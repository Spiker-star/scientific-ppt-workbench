# 统一入口与交接

本仓库是人工审稿驱动的工作室，不是已完成的一键论文到PPT服务。A沉稳学术与C现代科技保留为候选，B不再用于新稿。旧文件均保留。

## 如何使用

1. 把PDF交给ChatGPT，说明汇报类型、语言、页数、时长。
2. 要求输出逐页大纲。每页包含标题、核心论点、来源页码/图号、拟用布局、待核实问题。
3. 把确认后的大纲写入 task.yaml，并将PDF放到Codex能读取的本地路径。通过附件下载/上传或实际复制文件交接；两个会话不会自动共享文件。
4. 在Codex中说：请按这个仓库的AGENTS.md和task.yaml制作PPT，先核对证据，大纲未经确认不要生成终稿，不调用付费API。
5. 逐页看预览，确认内容与视觉，再导出PPTX。图片只保证可移动替换；原生文本、框图及新增数据图分别检查编辑性。

/make-ppt 目前不是已安装的斜杠命令。等价自然语言是：按 Research PPT Studio 的 task.yaml 开始制作科研PPT。

## 本地任务检查

`./.venv312/Scripts/python.exe scripts/make_ppt.py task.yaml`

任务文件采用JSON语法，属于YAML 1.2的合法子集，可无需新增依赖读取。检查不会自动批准大纲，不会调用API，也不会假装完成论文理解。它输出可执行的本地示例构建建议；真实论文仍由Codex按交接内容执行。

## 版式选择

背景用问题递进或现象对照；研究内容用任务分解；路线用阶段与方法对应；机制用中心关系及证据标注；结果用主图和辅助对比；总结区分发现、局限与下一步。统一字体配色与边距，避免所有页固定三栏。

已有可复现的离线PPTX构建、数据表嵌入、Windows兼容测试及编辑回读。六类布局尚未全部实现为独立可运行组件，论文自动理解与真实PaperBanana生图未打通。MFI真实论文样张仅本地保存，不能将合成示例当作论文结果。

## 六布局入口更新

六种布局现在在 layouts/library.mjs 中有可运行分支，examples/six-layout-task.yaml 含全部六类的内容示例。它们是程序组件样例，不是已批准的高质量视觉终稿，机制连接与图像证据需要逐任务设计。

设置此前教程中Codex自带运行库环境变量后，可执行：

`./.venv312/Scripts/python.exe scripts/make_ppt.py examples/six-layout-task.yaml --build --output output/my-six-layout-demo.pptx`

输出路径必须在项目内且不存在。自动构建目前只接受经确认的中文完整内容任务；英文/双语仍可由Codex调用既有双语构建器人工适配。不会用中文偷偷替代所选语言，不会自动确认大纲，不会调用付费模型。

视觉检查发现组件样例仍较稀疏，机制连接需进一步细化。文件能渲染不等于已经达到用户参考稿的视觉标准。下一步应将已认可的真实论文页面抽象为更丰富的组件，而不是把样例直接作为最终模板。

## 已验收主题版本1.0.0

A与C并列正式保留，任务中必须显式选择 palette: A 或 C，无唯一默认。B只保留历史样张。主题配置与渲染器快照位于 themes/research-framework-fusion/1.0.0，manifest.json记录哈希。后续修改必须复制到新版本目录，不能改写已验收快照；旧稿仍可回滚到原目录与Git提交。

任务可填page_type为background/content/roadmap/mechanism/results/summary，入口在layout缺省时自动映射至六类布局。显式layout优先；此规则按内容类型匹配，不宣称已经具备自动理解论文的能力。

论文交接：把PDF附件和确认后的大纲文件实际交给Codex，指定A或C、语言、页数、时长。中文/英文/双语真实论文制作先分别核对术语和证据，再逐页制作。目前自动六布局入口仍只验证中文，英文与双语需Codex人工适配及验收，不能绕过语言门禁。

修改时说：保留主题版本和数据，只修改第N页的某项内容，重新渲染该页并检查。旧文件不覆盖，输出使用新版本名。真实论文PDF与原图不上传公开GitHub，公共仓库仅保存允许公开的大纲、配置、源码与报告。
